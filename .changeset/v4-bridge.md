Rewrite the package. The sets of Mini Apps methods and events are unchanged, the API around them changed.

**Errors and async**

- Remove `fp-ts`. All `xFp()` functions are replaced with `safeX()`, which return `Result<E, T>` (`{ ok: true, data } | { ok: false, error }`). Add the `ok`, `err`, `unwrap` and `throwing` helpers. Only expected errors (timeout, invalid response, etc.) end up in a `Result`, environment and misuse errors are still thrown.
- Remove `BetterPromise`. Functions return a regular `Promise`, cancellation goes through `AbortSignal`: the `abortSignal` option is renamed to `signal`, `.cancel()` and `CancelledError` are removed, an aborted call rejects with `signal.reason`.
- `TimeoutError` is now the package's own error class with `.data.timeout`.
- Move errors to `error-kid` v3. Every error class has a static `.is(value)` method, most errors got a `.data` field and better messages. `InvokeCustomMethodFailedError.name` is now `'InvokeCustomMethodFailedError'`. Add `StartParamTooLongError`, thrown by `createStartParam`.

**Renames**

- `on` / `off` → `onEvent(event, fn, { once?, signal? })` / `offEvent(event, fn)`; `on('*')` / `off('*')` → `onAnyEvent` / `offAnyEvent`.
- `request2` → `request`, `requestFp` / `request2Fp` → `safeRequest`, `invokeCustomMethodFp` → `safeInvokeCustomMethod`, `createStartParamFp` → `safeCreateStartParam`, `retrieve*Fp` → `safeRetrieveLaunchParams`, `safeRetrieveRawLaunchParams`, `safeRetrieveRawInitData`.
- `isTMA('complete', opts)` → `isTMAAsync({ timeout?, signal? })`.
- `debug()` → `isDebug()`, `targetOrigin()` → `getTargetOrigin()`, `logger()` / `logger.set()` → `getLogger()` / `setLogger()`.
- `mockTelegramEnv({ onEvent })` → `mockTelegramEnv({ onMethod })`.
- Types: `SubscribeListener` → `AnyEventListener`, `EventWithPayload` / `EventWithoutPayload` → `EventNameWithPayload` / `EventNameWithoutPayload`, `MethodVersionedParams` → `MethodVersionedParam`, `RetrieveLaunchParamsResult` → `LaunchParams`.
- Add `parseLaunchParams`, `safeParseLaunchParams` and `serializeLaunchParams` (previously in `@tma.js/transformers`).

**Removed**

- `postEventFp`, `decodeBase64UrlFp`, `decodeStartParamFp`, `isTMAFp`.
- `resetGlobals()`, `postMessage`, `postMessageImpl`, `applyPolyfills()`.
- Re-exports of `createLogger`, `deepSnakeToCamelObjKeys`, `CancelledError` and the `Logger*`, `LogLevel`, `DeepConvertSnakeKeysToCamelCase` types.

**Behavior changes**

- `request` with an array of events always resolves to `{ event, payload }`. An exception in `capture` rejects the request.
- `invokeCustomMethod` takes `requestId` in the options, it's optional and generated by the new `createRequestId()` by default.
- Subscribing the same listener twice does nothing. An exception in a listener is logged and doesn't affect other listeners. In debug mode events are logged only while there is a subscriber.
- `emitEvent` accepts only known events and also forwards them to `window.Telegram.WebView.receiveEvent`. `viewport_changed` and `popup_closed` payloads are normalized.
- `postEvent` is a single generic function `<M>(method: M, ...args: MethodArgs<M>)`. Methods without parameters are sent with `eventData: ""`, as in the official SDK.
- **`LaunchParams.tgWebAppData` is now a raw string.** Use `@tma.js/init-data` to parse it. The launch params schema strips unknown keys and requires non-empty `tgWebAppPlatform` and `tgWebAppVersion`. Launch params are also read from the official SDK's `sessionStorage['__telegram__initParams']`. The sessionStorage key changed from `tapps/launchParams` to `tma.js/launch-params`.
- `mockTelegramEnv` returns a restore function and accepts `launchParams` as `string | URLSearchParams | LaunchParams`.
- `getReleaseVersion` returns `undefined` instead of `null`, `compareVersions` returns `-1 | 0 | 1`, `hasWebviewProxy()` takes no arguments, `decodeBase64Url` throws `TypeError` on invalid UTF-8.
- Logger: `setLogger({ log, warn, error })`. Only `log` depends on debug mode.

**Types**

- `Methods[M]` is now the parameters type itself. Use `MethodParams<M>` instead of `Methods[M]['params']`.
- Add `MethodArgs`, `EventListenerPayload`, `AnyEvent`, `OnOptions`, `EmitEventArgs`, `RequestFnArgs`, `RequestFnOptions`, `MockedMethodCall`.
- `RGB`, `Version`, `Platform` and `ThemeParams` moved here from `@tma.js/types`. `ThemeParams` got `section_separator_color`, `KnownThemeParamsKey` is removed.

**Build**

- The IIFE global is renamed from `tapps.bridge` to `tmajs.bridge`.
- Dependencies: remove `fp-ts`, `better-promises`, `mitt`, `@tma.js/signals`, `@tma.js/toolkit`, `@tma.js/transformers`, `@tma.js/types`; upgrade `error-kid` to 3 and `valibot` to ^1.5.
